# Authentication hardening: dependency remediation

The starting working tree was `security-dependency-fixes`, HEAD `c4a5653`, with
uncommitted Task 3 Auth changes. A local pre-change snapshot was preserved under
ignored `.tmp/security-hardening/before`. No branch switch, commit or prior
migration rewrite was performed. The untracked source/schema ZIP archives were
left untouched and are not implementation files for this task.

Initial `npm audit --json` exited 1 with 11 affected dependency entries: one
critical, seven high and three moderate. `npm audit --omit=dev --json` exited 1
with ten entries: seven high and three moderate. Parent and leaf entries can
refer to the same advisory; these are not eleven independent vulnerabilities.
`npm ls body-parser` exited 0; `npm outdated` exited 1 because updates existed.

The initial installation of a direct proxy helper exposed an additional critical
[proxy-addr GHSA-jqcg-44mw-7w3h / CVE-2026-90711](https://github.com/advisories/GHSA-jqcg-44mw-7w3h).
The final direct and Express-resolved helper is **2.0.8**, the patched version.
Tests cover untrusted forwarding headers, canonical mapped addresses, right-edge
trust boundaries and incorrectly short IPv4-mapped IPv6 trust subnets. No
vulnerable 2.0.7 helper is intentionally retained.

New SMTP delivery uses Nodemailer 10.2.1 with environment-only credentials, TLS
validation and bounded timeouts. No provider credentials were read or used to
send a third-party email. SMTP readiness and live deliverability are separate:
tests use a controlled mailer; production must configure an approved provider.

The final clean `npm ci` completed with exit code 0. Fresh `npm audit --json`
and `npm audit --omit=dev --json` both completed with exit code 0 and zero
vulnerabilities in every severity category. The initial audit contained 11
full-tree entries (one critical, seven high, three moderate) and 10 production
entries (seven high, three moderate). These results describe the resolved
lockfile at review time; repeat the audits before release.

The lockfile is authoritative and must be verified with `npm ci`, fresh full and
production audits, `npm ls body-parser multer uuid proxy-addr`, build, maintained
tests and isolated PostgreSQL verification. Do not run `npm audit fix --force`.
No major NestJS, Prisma, Express or ExcelJS upgrade was performed. See
[Auth API](auth-api.md) for migration rollout, proxy settings, refresh replay,
password-recovery and Android requirements.
